# 文字議会の設計

最終出力は ASCII の `HELLO WORLD` と LF、12 バイトだけ。11 文字を表示するために、11 件の議案、各 5 人の記名投票、11 通の成立証明、議事録を本当に通過させる。

## 第 1 週: 2026-10-03

1. `proposal.json`: 固定の文字コード列を、位置番号と議案番号のある 11 件の議案にする
2. `ballot.json`: 各議案を位置・ASCII・議題との一致・件数・印字可能性の 5 委員が検査。固定 seed から発言順を決め、全員の投票を保存する
3. `certificate.json`: 定足数 5 と賛成 3 以上を確認し、投票のハッシュと成立証明の seal を作る
4. `minutes.json`: 成立証明を照合し、位置順の文字と証明番号を議事録に記載する
5. `show`: 全成果物を先頭から再検証し、議事録に記載された文字だけを組み立てて表示する

前段の内容から後段を再計算できる固定 seed・固定入力方式。途中のファイルを削除・変更したり、工程を飛ばすと失敗する。ハッシュは改変検出用で、電子署名・外部認証・秘密鍵ではない。時刻・乱数・外部サービスに結果を依存させない。同じ内容の完全な台帳は別の run-id にコピーしても検証可能。run-id は保管場所の名前で、成果物の真正性や別実行由来の否認を保証しない。

`pipeline.json` が実行順、週、依存関係、seed の正本。実装側の登録と完全一致を要求する。自動的な外部モジュール読み込みは行わない。

## 小さく、有限に、読める範囲で

Linux + CPython 3.12.14 で検証する。Python 標準ライブラリのみを使用し、インストールや実行時ダウンロードは不要。高負荷モードはない。

- 監督 1 プロセスと、固定された処理だけを行うワーカー 1 プロセス
- 同じ 1 CPU への affinity。ワーカー CPU 時間 8 秒、監督 2 秒
- ワーカー仮想アドレス空間 192 MiB、監督 64 MiB。各プロセスに RLIMIT_AS を適用する
- 起動準備から 10 秒の経過時間を監督し、超過時はワーカーのプロセスグループを終了して回収する
- RLIMIT_FSIZE は各ファイル 1 MiB。成果物は固定 4 ファイルで各 64 KiB 以下。取得ログ・標準出力は合計 64 KiB 以下
- ロック用空ファイルを除き、1 回の通常実行が生成する内容は最大 320 KiB。32 MiB の予算より小さく保つ
- 成果物の書込み先はこの checkout の `.hello-world/runs/<run-id>`。固定ファイル名、重複拒否、symlink 拒否、regular-file 検査を行う
- ワーカーは外部通信・追加プロセス・スレッド・動的コード実行を使わない。実行前に当該コードと変更差分をレビューする

これは一般的な OS 隔離 sandbox ではない。通信やファイル書込みをカーネルで全面遮断していない。RLIMIT_AS は RAM 全体の cgroup 上限ではなく、RLIMIT_FSIZE はディレクトリ総量の上限ではない。複数の独立実行全体、OS キャッシュ、Python 外の既存プロセスには予算は適用されない。任意のコード、悪意あるコード、レビューしていない追加ライブラリをここで実行してはならない。別プロセスが同時に作業ディレクトリを差し替えるような敵対的ファイル操作も対象外。

元の強い隔離方式は実行環境で利用できないため、この低負荷方式を採用する。Linux 機能や rlimit の適用を確認できない環境では fail closed とし、上限を黙って外さない。CPU affinity とプロセス自身の rlimit は起動したプロセスに限って適用し、OS 全体の設定を変更しない。

## 失敗と公開

stdout は監督が保持し、ワーカー終了コード 0 と出力形式を検証したときだけ転送する。失敗時の stdout は空、説明は stderr、終了コードは非 0。途中の失敗成果物は検証用に残る。同じ run-id で上書きしない。

公開前に全試験・コードレビュー・最新 remote の照合を行う。競合・停止・排他不明・試験失敗なら公開しない。週の重複を作らず、通常の fast-forward 以外は使わない。
